  This guide covers every known issue you may encounter when
  running facts. on Linux. Work through the issues in order.

  QUICK FIXES FIRST:

       https://github.com/WEAREOSE/facts
       Replace LinuxLaunch.sh on the drive with the new one.

================================================================
  HOW THE LAUNCHER WORKS (so you can debug it)
================================================================

  There are two ways to start facts. on Linux:
    - Double-click "Launch facts (Linux)" on the drive.
      This is the easiest path and works on most desktops.
    - Or open a terminal and run: bash LinuxLaunch.sh
      Same launcher, just for terminal folks.

  facts. on Linux uses a native llama.cpp build with Vulkan,
  which means GPU acceleration works on ANY modern GPU vendor:
  NVIDIA, AMD, and Intel (including integrated graphics).

  Files involved:
    Launch facts (Linux)            -- double-click launcher
    LinuxLaunch.sh                  -- terminal launcher script
    .system/linux/llama-cli         -- the native AI engine
    .system/linux/libggml-vulkan.so -- Vulkan GPU backend
    .system/linux/lib*.so           -- supporting libraries
    .system/Qwen3.5-4B-abliterated.Q8_0.gguf   -- main model (4.5GB)
    .system/Qwen3.5-4B-abliterated.Q4_K_M.gguf -- light model (2.7GB)

  The launcher picks the model for you: machines with 16GB+ RAM
  get the Q8 model, everything else gets the Q4 model. It also
  sizes the context window to your RAM automatically: 8K by
  default, 16K on 16GB machines, 32K on 32GB+. (The README
  mentions the model supports up to ~262K. That is the model's
  maximum, not the session default.)

  On FIRST launch, the launcher runs a one-time GPU vs CPU
  benchmark and picks whichever is faster on YOUR hardware.
  You'll see:

    GPU: benchmarking GPU vs CPU (one-time, ~30 seconds)...

  It can take anywhere from 30 to 90 seconds and may LOOK
  frozen while it runs. It is not frozen. Let it finish. The
  decision is cached so future launches skip the benchmark
  and start immediately.

  Cache files (hidden, inside .system/):
    .gpu_verified  -- saved if your GPU beat your CPU
    .cpu_mode      -- saved if your CPU beat your GPU

  A FAILED benchmark saves nothing: the launcher uses CPU for
  that session only and re-tests on the next launch. If you
  ever change GPU drivers or upgrade hardware, delete whichever
  cache file exists and the launcher will re-bench next launch.

  A few more things that are normal:
    - An OSE logo (ASCII art) prints at the top on launch. If
      it's missing for some reason, everything still works.
    - "Cache Status: Wiped Clean [Zero-Log Mode]" means your
      chat history was wiped. This happens at every launch AND
      at exit. Exiting also clears the screen and scrollback,
      so nothing you typed sticks around.
    - Thinking mode is OFF by default (instant answers). If you
      want to turn it on, see READ_ME_FIRST.txt on the drive,
      under ADVANCED TWEAKS.


================================================================
  ISSUE 1: "Permission denied" when launching
================================================================

  CAUSE: The launcher doesn't have execute permission, OR your
  file manager opens it in a text editor instead of running it.
  (exFAT drives can lose the execute bit depending on how your
  distro mounts them.)

  EASIEST FIX (works on every distro):
    1. Open a terminal.
    2. Navigate to the drive (see ISSUE 2 if you can't find it).
    3. Run with bash directly:

       bash LinuxLaunch.sh

    Bash invokes the script regardless of execute permission.
    You don't need chmod for this approach.

  ALTERNATIVE FIX (one-time chmod, then double-clickable from
  some file managers):
    1. cd /media/$USER/facts
    2. chmod +x "Launch facts (Linux)" LinuxLaunch.sh
    3. ./LinuxLaunch.sh
       (or double-click "Launch facts (Linux)")


================================================================
  ISSUE 2: Drive doesn't appear or can't find the files
================================================================

  CAUSE: Linux mounts USB drives in different locations
  depending on the distro.

  COMMON MOUNT POINTS:
    - /media/yourusername/facts          (Ubuntu, Debian, Mint, Pop)
    - /run/media/yourusername/facts      (Fedora, RHEL, openSUSE)
    - /mnt/facts                          (manual mount)

  HOW TO FIND YOUR DRIVE:
    1. Run: lsblk
    2. Look for an entry labeled "facts".
    3. Note the MOUNTPOINT in the last column.
    4. Navigate there: cd "<mount point>"

  If lsblk shows the drive but no MOUNTPOINT, it isn't
  auto-mounted. Mount it manually:
    sudo mkdir -p /mnt/facts
    sudo mount /dev/sdX1 /mnt/facts        (replace sdX1 with yours)


================================================================
  ISSUE 3: "cannot execute binary file: format error"
================================================================

  CAUSE: An outdated launcher from before v1.5 tried to run the
  wrong platform's binary on Linux. If you see this error, your
  LinuxLaunch.sh is old.

  FIX:
    1. Download the latest launcher from:
       https://github.com/WEAREOSE/facts
    2. Click "LinuxLaunch.sh" -> click the download icon
       (top-right) to save it.
    3. Drag the downloaded file onto your drive's root,
       replacing the old one when asked.
    4. Eject and re-plug the drive.
    5. Run: bash LinuxLaunch.sh

  The current launcher uses .system/linux/llama-cli (a native
  Linux binary that's already on your drive). There is nothing
  else to download, the whole engine ships aboard.

  If instead you see:

    [ERROR] llama-cli not found in .system/linux/

  the engine folder itself is missing or damaged. Reach out to
  us (see the bottom of this guide) and we'll make it right.


================================================================
  ISSUE 4: The AI loads but is extremely slow
================================================================

  CAUSE A -- Wrong CPU/GPU choice cached:
    The launcher's first-launch benchmark might have made the
    wrong decision (rare, but possible if your system was busy
    during the bench).

    To force a re-bench:
       rm /media/$USER/facts/.system/.gpu_verified
       rm /media/$USER/facts/.system/.cpu_mode
       bash /media/$USER/facts/LinuxLaunch.sh

    Watch the output for a line like "Benchmark: GPU=12.4 t/s,
    CPU=6.1 t/s" followed by which one wins. If the result
    looks wrong, stop the launcher and ask the LLM Engineer
    for help.

  CAUSE B -- Not enough RAM:
    Need at least 8GB total, 4GB free. If free RAM is low the
    launcher warns you:

      [WARNING] Low available RAM. Close other apps for best performance.

    Check with: free -h
    Close other apps if memory is tight.

  CAUSE C -- USB 2.0 port:
    The initial model load is slow on USB 2.0 (the 4.5GB model
    over USB 2.0 takes a couple of minutes to load). Use a
    USB 3.0+ port if available -- usually blue inside the
    connector.

  CAUSE D -- Swap thrashing:
    If your system is swapping to disk, performance tanks.
    Check with: free -h
    If "Swap" used > 100MB, close other apps.


================================================================
  ISSUE 5: Force CPU mode, force GPU mode, or re-test
================================================================

  THE LAUNCHER DECIDES AUTOMATICALLY:
    On first launch, it benchmarks GPU vs CPU and picks
    whichever is faster (with a 10% margin to avoid flapping).

  TO FORCE CPU MODE (skip GPU entirely):
    Create the cache file manually:
       echo "manual override" > /media/$USER/facts/.system/.cpu_mode

  TO FORCE GPU MODE (skip the benchmark):
    Create the verified marker:
       echo "manual override" > /media/$USER/facts/.system/.gpu_verified

    Note: only force GPU if you've confirmed it's actually
    faster. On older Intel iGPUs (UHD 6xx/7xx series), the GPU
    is often slower than a modern CPU due to memory bandwidth
    limits, and the launcher correctly picks CPU.

  TO RE-RUN THE BENCHMARK (e.g. after a driver update):
    Delete BOTH cache files:
       rm /media/$USER/facts/.system/.gpu_verified
       rm /media/$USER/facts/.system/.cpu_mode

    Then run the launcher again. It'll re-bench and rewrite
    one of the cache files based on the new result.


================================================================
  ISSUE 6: Benchmark looks frozen, hangs, or comes back
           inconclusive
================================================================

  FIRST: the benchmark can take up to ~90 seconds and shows no
  progress while it runs. That is normal, not a hang. Only read
  on if it genuinely never finishes or reports a failure.

  CAUSE A -- Buggy Vulkan driver:
    Some older Vulkan drivers crash or hang under benchmark
    load. This is unfortunately common on certain hardware.

    The launcher guards each benchmark run with a timeout. If
    the bench crashes or times out, you'll see:

      Benchmark inconclusive this launch — using CPU for now, will re-test next launch.

    That's the launcher protecting you from a hang. It runs on
    CPU for that session and tries the benchmark again next
    launch (a failed bench is never cached, so a one-off hiccup
    can't lock your GPU off forever). If it fails every launch
    and the retry annoys you, force CPU mode per ISSUE 5.

  CAUSE B -- Missing Vulkan runtime:
    Some minimal distros don't ship Vulkan ICDs by default.
    If your distro has no GPU vendor's Vulkan loader installed,
    the bench will fail and CPU mode is used. That's still fine.

  CAUSE C -- Conflicting Vulkan layers:
    Tools like RivaTuner / OBS / HudSight inject Vulkan layers
    that interfere with compute. The launcher disables them
    automatically via VK_LOADER_LAYERS_DISABLE, but if you
    have something exotic loaded, the bench may still fail.

  WHAT TO DO:
    Just let it use CPU mode. The 4B model runs fine on any
    modern CPU (3-8 t/s on an i5/i7, faster on Ryzen).


================================================================
  ISSUE 7: The AI crashes or freezes mid-conversation
================================================================

  CAUSE: Context window full, or out of RAM. The context window
  is sized to your RAM (8K default, 16K on 16GB machines, 32K
  on 32GB+), and very long conversations can fill it.

  FIX:
    Close the terminal and re-run the launcher. The launcher
    wipes all history on each launch -- start fresh. (It also
    wipes on exit, so nothing lingers either way.)


================================================================
  ISSUE 8: Distro-specific notes
================================================================

  GLIBC REQUIREMENT (all distros):
    The bundled engine needs glibc 2.32 or newer. Any mainstream
    distro released from about 2021 onward is fine. Check with:
       ldd --version

  UBUNTU / DEBIAN / MINT / POP!_OS:
    Should work out of the box. Drive auto-mounts to
    /media/$USER/facts. Double-click "Launch facts (Linux)"
    or run: bash LinuxLaunch.sh

  FEDORA / RHEL / OPENSUSE:
    Drive auto-mounts to /run/media/$USER/facts.
    Adjust paths in this guide accordingly.

  ARCH / MANJARO:
    May need udisks2 for auto-mount:
       sudo pacman -S udisks2
    Then unplug and re-plug the drive.

  NIXOS:
    Native binaries may need patchelf if the dynamic linker
    differs from /lib64/ld-linux-x86-64.so.2:
       nix-shell -p patchelf --run "patchelf --set-interpreter \
         /lib64/ld-linux-x86-64.so.2 .system/linux/llama-cli"
    Or just run the launcher inside a steam-run / FHS env.

  ALPINE / MUSL-BASED:
    Not currently supported -- the bundled binary is glibc-only
    (2.32+). Install a glibc compatibility layer (gcompat) or
    use a glibc-based distro.


================================================================
  ISSUE 9: GPU drivers updated -- AI suddenly slow or broken
================================================================

  CAUSE: A driver update can change Vulkan behavior. Your
  cached benchmark result from a previous launch might no
  longer be accurate.

  FIX: Delete the cache and re-bench:
    rm /media/$USER/facts/.system/.gpu_verified
    rm /media/$USER/facts/.system/.cpu_mode
    bash /media/$USER/facts/LinuxLaunch.sh
